## Data model and migration

`WeightGoalMonth` → `weight_goal_months`: `id text pk`, `seq serial`, `user_id text` FK users (RESTRICT), `year int`, `month int` CHECK 1–12, `goal_kg double precision`, `direction text` CHECK in ('gain','lose'), `created_at`, `updated_at` timestamptz(3). Unique `(user_id, year, month)`. No `deleted_at`: never deleted, not in the Papelera (REQ-47). "Latest" = greatest (year, month) in `latestRow`, never by `seq`.

- **Storage wiring:** the record type (`WeightGoalMonthRecord` in types.ts) lands in T017 with `weight-goal.ts`, which takes its values; the new AppDb collection (types.ts key, `emptyDb`, store.ts `models`/`insertOrder` (last)/`scalarFields`, default `ownedBy`), because the assistant computes over AppDb and is unit-tested over `memDb()`. Prisma 7.10 removed `--from-schema-datamodel`/`--to-schema-datamodel` (`node_modules/prisma/build/cli.js`: "was removed. Please use `--[from/to]-schema`"). ## Direction and reached rule

## Toasts, focus and announcements (sonner 2.0.7, read in node_modules)

- **Sonner facts:** pauses on pointer hover, not on focus; an existing id updates in place; the toaster is an `aria-live="polite"` section after the app (`ThemeRuntime`, `position="top-right"`, `closeButton`, `richColors`); toasts are `tabindex=0`; Alt+T focuses the list. Its list `onFocus` records the element focused before (`index.mjs:1120-1127`) and `onBlur` sends focus back there whenever focus leaves the list (`1109-1118`), including by Tab, which loops (into the toast, past "Deshacer", back).
- **Decision: we handle focus leaving the toast ourselves, and keep the toast in sonner.** The Deshacer toast is `toast.custom(<WeightToast/>, { id: "nt-weight-saved", duration: Infinity, dismissible: false })`, and every focusable inside `WeightToast` carries `data-dismissible="false"`. Sonner's `onFocus` returns early for such targets (`1121-1122`), so it records nothing and its blur and unmount handlers never move focus; Tab and Shift+Tab leave the toast to the next or previous element in document order, with no loop. `WeightToast` owns the one focus move: when it closes (expiry, Deshacer, replacement by an error) while focus is inside, focus goes to the Peso knob. Reason: rendering outside sonner would need our own stacking beside sonner's error toasts, which D21h requires on screen together, and our own copy of the app's top-right position (D21g). Cost: relies on that early return; guarded by the e2e Tab walk (T044) and the lockfile (upgrades need the user's yes). Side effect: no swipe-to-dismiss on this toast.
- **The weight error toasts get the same treatment** (failed save, failed Deshacer): `toast.custom(<WeightToast kind="error" …/>, { id: "nt-weight-error", dismissible: false })`, focusables marked `data-dismissible="false"`, the same focus move to the knob when it closes with focus inside (sonner does not pause on focus, so an error toast can expire while focused). Reason, from the source: a plain `toast.error` cannot be fixed. Its `<li>` would carry `data-dismissible="false"`, but sonner's close button (rendered for non-custom toasts because the app's Toaster has `closeButton`, `index.mjs:779`) carries no such mark, so focusing it records the previous element and the loop returns; and with `dismissible: false` that close button does nothing (`783`). With `toast.custom` sonner renders no close button and no styling (`650`, `779`), so `WeightToast`'s error variant draws its own: text, icon and colours from sonner's rich-colour error variables (`--error-bg`, `--error-border`, `--error-text`) so it looks like the app's other error toasts, and a close button with the same accessible name as the app's other toasts (sonner's default "Close toast"; the Toaster sets none) that calls `toast.dismiss(id)`. Lifetime stays the app's normal one (sonner's 4 s default, its hover pause; D20l keeps the 8 s pausable timer for Deshacer only). The goal toasts in Configuración stay ordinary sonner toasts (not weight toasts, outside this decision).
- **Known limit, Alt+T.** Alt+T focuses sonner's `<ol>` (`1053`), which carries no `data-dismissible` and takes no props for one, so `onFocus` records the element focused before Alt+T; when Tab later leaves the list, sonner returns focus there once (and overrides `WeightToast`'s move to the knob if the toast closes while focus is inside after Alt+T). It is one return, not a loop: the record is cleared, the next Tab follows document order, and a later Tab into the toast is the marked path. Fixing it would mean stopping focus events before sonner sees them or leaving sonner; not done. Recorded under Risks; T044 asserts the actual behaviour.
- **Lifetime (D20l):** `WeightToast` runs the 8 s pausable timer from `peso-logic.ts`, paused on `pointerenter`/`focusin`, resumed on `pointerleave`/`focusout`; dismisses itself at expiry.
- **Which toasts show (REQ-29, 39, 40, 51, D21h):** a success with nothing queued after it shows the Deshacer toast, replacing an older one in place. A failed save or Deshacer shows the error variant of `WeightToast` (above) with id "nt-weight-error" (a newer error replaces an older one) and dismisses a showing Deshacer toast. A later success never dismisses an error toast about a different save: with save 1 failed and save 2 succeeded, both toasts show. After a successful Deshacer the toast closes and no toast shows.
- **Position (D21g):** the app's normal top-right. T005 measures whether a top-right toast box covers the planned − / + at the five sizes, 390×844 and 360×800, at scroll 0 and with the Peso tile scrolled to just below the sticky top bar. Only if it covers them: weight toasts use `position: "bottom-center"`, and T005 then checks it does not cover the assistant button at 360px wide; if it would, that is a new question for the user at T006.
- **Keyboard reach (REQ-27):** the toast sits at the end of the document; T005 counts Tab stops from "+"; Alt+T reaches it at once. Focus inside pauses the timer.
- **After a successful Deshacer:** a visually hidden `role="status"` in the Peso tile says "Peso, 71.0 kg" (REQ-51).
- **Which save Deshacer undoes:** saves are single-flight and coalesced (one in flight, latest pending kept), so the server applies them in gesture order; Deshacer sends the `previous` of the save its toast belongs to (71.0 → 71.5 → 72.0 restores 71.5).
- **Limits and focus (REQ-50):** − / + use `aria-disabled="true"` and ignore activation at a limit (the `disabled` attribute would drop focus to `<body>`); a hold stops at the limit.
- **When a gesture saves nothing (D21f):** when the needle never moved during the gesture, or when it ends on the stored weight rounded to tenths. With no weight yet, ending on 50.0 after moving saves 50.0; with a stored 28.0 (needle at 30), ending on 30.0 after moving saves 30.0.
